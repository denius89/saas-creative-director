# Creative reference research

Read `docs/REFERENCE_RESEARCH_POLICY.md`, `knowledge/references/curated-sources.yaml`, and only the pattern files relevant to the approved value story. Research only after strategy approval. Populate both `artifacts/reference-library.json` using `core/schemas/reference-library.schema.json` and `artifacts/pattern-library.json` using `core/schemas/pattern-library.schema.json`; register every concrete source.

Use all four tiers when useful: A curated studio benchmarks, B direct client competitors, C strong same/adjacent-category work, and D exploratory cross-industry mechanisms. Tier A is a seed, never a stopping condition. Search for the best way to explain the specific value story or product mechanism—not for generically attractive SaaS videos.

For each work capture industry, project/video type, narrative structure, composition patterns, hierarchy/focal point, UI and illustration usage, motion and transition patterns, pacing, text density, strengths, weaknesses, reusable principles, risks/non-copy constraints, URL, screenshots/timestamps, inspection method/date, and confidence. Unknown fields remain `null`; never infer motion from a thumbnail.

The reference library contains concrete works and scene observations. The pattern library contains only abstracted, reusable mechanisms with multiple-example support or an explicit experimental label. The synthesis must identify patterns, overused devices, opportunities, and explicit non-copy constraints. Reject references that are visually attractive but strategically irrelevant.
