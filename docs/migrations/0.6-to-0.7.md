# Migration from 0.6 to 0.7

This guide applies when updating from 0.6 to 0.7. Existing 0.5/0.6 project data remains readable; migration is additive unless a maintainer explicitly chooses to upgrade a storyboard to contract 1.1.

## Before updating

Finish the current operation, save Figma work, and use the updater so it creates a transaction backup. Do not replace the repository folder manually. `INBOX/`, `projects/`, `config/`, `overrides/`, and `knowledge/custom/` are protected by the release policy.

The first update started by the published 0.6 launcher cannot copy the new `knowledge/current-motion/` and `knowledge/anti-patterns/` directories because that launcher used a fixed path list. Release 0.7 places a verified bootstrap copy inside `core`; on the next `scd` command, the new launcher creates missing directories and atomically completes compatible partial copies. A directory with changed files or unexpected paths is treated as a conflict and is preserved for manual review.

Old 0.6 backups did not contain the new release manifest and could contain an `INBOX` snapshot. Rollback accepts such a backup only from this installation's `.scd/backups` directory with its original versioned name. Current extraction limits and the old managed-path allowlist are applied, and the archived `INBOX` is ignored so current client materials survive.

## Existing approvals

Legacy approvals that do not contain an artifact revision and dependency digest become `STALE` when the project resumes. Review the exact current artifacts and approve them again. Creative Direction now occurs after motion direction and representative frames, so an older narrative-only approval does not unlock the storyboard.

## Existing storyboards

Legacy 0.5 and 1.0 storyboards remain valid. New causal scenes that need a visible temporal sequence should use schema 1.1 panel-sequence mode with stable object IDs, object presentations, meaningful states, bounded events, panels, and transition anchors. Do not synthesize missing product states merely to complete the new fields.

The update does not automatically split an approved legacy scene into panels. When a causal scene is deliberately revised, preserve its narrative purpose and semantic objects, add only the panels needed to read setup/action/result, and submit the new storyboard revision for review. A legacy one-board scene remains readable as a single-panel compatibility case until it is intentionally upgraded.

## Figma importer

Regenerate `figma-manifest.json` with the matching core version and load the plugin from the same release. Manifest 1.1 renders panel sequences; legacy scenes continue through manifest 1.0. Both create new draft boards when scene content or render context changes, reuse exact complete boards, and preserve human edits at scene level. Test the first import in a disposable Figma file and complete `docs/FIGMA_LIVE_VERIFICATION.md` before production use.

## Usage and billing

The default policy is advisory subscription use. The update does not enable Usage credits, purchase bundles, add an API key, or change models. Unknown token and cost fields remain `null`.
