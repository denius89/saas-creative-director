# Claude usage and billing

The default user runs this project in Claude Desktop → Code → Local with a Claude Pro or Max subscription. No API key is required by the product. Included usage is shared across Claude, Claude Desktop, and Claude Code, so another active conversation can affect the same allowance.

Included plan usage, paid Usage credits, and Console/API billing are separate. Usage credits are optional prepaid consumption after included limits and are billed separately. The project must never enable Usage credits, buy a usage bundle, set auto-reload, add an API key, or select another model on the user's behalf. If included usage is unavailable, save a checkpoint and resume after the plan window resets. An `ANTHROPIC_API_KEY` in the environment can route Claude Code through API billing instead of the subscription, so account settings and the Claude Usage page are authoritative; project estimates are not a bill or a percentage of a Max allowance.

To keep usage bounded, the workflow loads one stage skill and a compact context packet, reuses inspected reference records, expands two creative directions by default, retrieves at most three scene candidates, changes only affected scenes, and caps automatic repair/retry cycles. Local Figma rendering is deterministic and does not call a model for each node. The configured context target is converted to an approximate character budget at four characters per token; this is a context-shaping heuristic, not a measurement of Claude usage.

At every successful stage advance, the controller writes a `stage_boundary` event and a resumable checkpoint. All usage counts on that event remain `null`; it proves progress, not consumption. A separate `model_usage` event may contain stage, model/mode when reported, token counts when the host supplies them, tool/image counts, cache status, elapsed time, and whether a monetary value is estimated. Unknown values remain `null`. Subscription events cannot contain an invented dollar cost. An API or Usage-credit estimate requires an explicit price snapshot. Never record prompts, client text, screenshots, credentials, or API keys in the usage ledger.

The maintainer interfaces are `./scd prepare-runtime <project>`, `./scd record-usage <project> ...`, and `./scd usage-summary <project>`. Ordinary users do not need to run them; the orchestrator uses the same stage-boundary behavior. Stage-boundary records do not affect token totals. Among model-usage events, a total remains `null` whenever any included event lacks that measurement.

Official references: [Claude Code on Pro/Max](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan), [Usage credits for paid plans](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans), and [API environment variables](https://support.claude.com/en/articles/12304248-manage-api-key-environment-variables-in-claude-code).
