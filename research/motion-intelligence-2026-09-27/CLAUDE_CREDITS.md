# Как проект будет расходовать Claude Pro/Max

Проверено 27 сентября 2026. Основной вариант, выбранный пользователем: подписка Pro/Max. Настройки и баланс аккаунта знакомого не проверялись и не менялись.

## Три разных режима

| Режим | Что оплачивается | Решение для проекта |
|---|---|---|
| Включённое использование Pro/Max | Работа в пределах allowance подписки | Основной режим |
| Usage credits, в старых материалах Extra usage | Дополнительное использование за отдельную оплату по API-тарифам | Только по решению владельца аккаунта |
| Console/API | Отдельная API-биллинг система | Для нашего MVP не требуется |

В Settings → Usage можно отключить Usage credits; тогда остаётся только включённое использование. При включении доступны месячный предел расходов и опциональное автопополнение. Автопополнение покупает средства и не является бюджетом отдельного проекта. [Официальная инструкция Claude](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans)

Подписка сама по себе не оплачивает отдельный API. [Раздельная оплата подписки и Console](https://support.claude.com/en/articles/9876003-i-have-a-paid-claude-subscription-pro-max-team-or-enterprise-plans-why-do-i-have-to-pay-separately-to-use-the-claude-api-and-console)

## Рекомендуемая настройка для первого пилота

- Войти в Claude через аккаунт с Pro/Max; выбрать Code → Local и папку проекта.
- Проверить в Settings → Usage, что платное продолжение отключено, если нужны расходы только в пределах подписки. Продукт это состояние не меняет.
- Проверить активный способ авторизации. Если раньше на компьютере настраивался API, Claude Code может использовать его; диагностике достаточно показать режим, никогда сам ключ. [API environment variables](https://support.claude.com/en/articles/12304248-manage-api-key-environment-variables-in-claude-code)
- Начать с Standard preset: одна история, два направления, ограниченный research и локальные правки сцен.
- Если Claude сообщает об исчерпании включённого лимита, возобновить из checkpoint после доступного сброса либо самому решить вопрос дополнительных расходов. Skill не должен покупать кредиты или обходить ограничение.

## Что на деле экономит лимит

Повторно использовать утверждённые artifacts и library; читать только текущий stage packet; не запускать команду агентов на каждый проект; не перегенерировать всю историю ради одной сцены; строить Figma nodes локальным кодом; ограничить retry/QA cycles. Библиотеку референсов пополняем как отдельную общую работу, а не заново за счёт каждого клиента.

Включённый лимит используется также другими задачами аккаунта. Нельзя обещать фиксированное число видео-проектов на Max или вычислять процент allowance по API-прайсу. Указанная Claude оценка стоимости сессии и фактический счёт — разные показатели. Проверять плановое использование в интерфейсе Claude, а не по придуманному счётчику проекта. [Claude Code usage/costs](https://code.claude.com/docs/en/costs)

Обычный интерактивный skill не гарантирует жёсткий денежный или токенный потолок. Лимиты операций в MASTER_PLAN — правила процесса. Встроенные CLI `--max-budget-usd` и `--max-turns` имеют отдельную область действия print mode и не превращают Desktop skill в billing controller. [CLI reference](https://code.claude.com/docs/en/cli-reference)

## Приёмка реализации

После первого проекта записать доступные usage measurements, количество поисков/чтений/изображений/повторов, latency и качество handoff. Unknown оставить unknown. Повторить с той же задачей и оптимизированным context/cache. Только после этого выбирать стандартный профиль и говорить о достигнутой экономии. API-расчёты в исследовательской записке — иллюстрации, не цена проекта для знакомого.
